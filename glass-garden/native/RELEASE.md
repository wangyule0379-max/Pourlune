# Existing-app release path

Preparation only. Complete the current developer native batch, fix observed issues, freeze and obtain the parent's actual acceptance before creating the signed update. Protect F9, the old app/library, original frozen packages and signing material. No formal App Store/Play release is authorized by this runbook.

1. Read current App Store Connect build/version state through the existing Computer chat only when the accepted candidate is ready. Choose an unused build number from that evidence, not from the historical19. Keep the existing com.pourlune.app, original Pourlune Self group and existing2 testers; do not create groups/invite again.
2. Freeze a new web tag with package.mjs --sdk --ads. It verifies original sources, licensed resources and exact private SDK files; no CI copied-input shortcut. Stage that tag with stage-native.mjs TAG --production --version VERIFIED_VERSION --build-number VERIFIED_NUMBER. The staging command requires those explicit values and official test ads. It changes only ignored generated assets/stage metadata, so restore the QA stage before subsequent QA builds.
3. iOS Release must explicitly use PRODUCT_BUNDLE_IDENTIFIER=com.pourlune.app, GARDEN_APP_DISPLAY_NAME=Pourlune, matching MARKETING_VERSION/CURRENT_PROJECT_VERSION and GARDEN_PRODUCTION_SERVICES. The stage guard rejects QA identity, Debug, version mismatch and conflicting flags. Reuse only previously verified existing manual certificate/profile; never allow automatic provisioning/key generation or reset. The source project defaults to CODE_SIGNING_ALLOWED=NO. Archive/export only after acceptance, with the same reviewed source/resources. No production runtime or QA data upload during compilation.
4. Android production requires gardenProductionServices=true plus gardenVersion/gardenBuildNumber matching the verified stage, and only assembleRelease/bundleRelease tasks. It stays unsigned; existing upload key is not generated/reset or implicitly read. This does not authorize Play upload or reopening the paused commercial AdMob integration. QA builds retain their independent identity and may use the existing debug certificate for minified runtime tests.
5. Audit final identity/version/signature/profile/entitlements, all frozen web/SDK/resource hashes, NoAdID/NPA/PG/official sample units, app/vendor privacy manifests, actual encryption/linkage and live privacy/support disclosures. Do not infer export status from the simulator framework shim. Preserve original source/archive/Organizer-export variants and explain any signing-only differences. Match the precise current CI source; CI compile-only success does not replace native SDK/backend results.
6. Upload with the existing authenticated Xcode/App Store Connect path. Request normal login only on an actual authentication blocker; never ask for passwords/codes. Reuse prior authorized applicable compliance choices only when supported by this package's facts. Distribute only the accepted build to the original group, read back processing/testing status and eligibility. Upload receipt is not installability; physical phone upgrade/audio/haptics remain separate honest limits.

QA commands are in README.md. Current production config is guarded but has not been executed or declared store-ready. Test/build guards use synthetic version fixtures only, not actual store allocations. No new public SDK source, accounts, identifiers or backend registrations are created.
