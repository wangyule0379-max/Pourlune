首次打开 → 欢迎 → 关内教学 → 普通对局 → 自动记入通关与收藏 → 通关页 → 下一关。

每 4 个首次普通通关节点：通关页 View patch → 新拼片页 → Next level 或 View collection。奖励在打开结果页之前已经记录。

页面中的第 12 关作为统一示例：开始时已完成 11 关、收藏 2/5；首次通关后为 12/20、3/5，还需 8 关完成 Color Studio。


# Pourlune · 产品逻辑与页面契约

> 设计评审稿。面向欧美成年休闲玩家，界面使用简短美式英语（统一使用 color）；本文使用中文说明。沿用已经确认的明亮针织场景、玻璃瓶与浅色半透明液体。首版范围为离线可玩的单人倒液体解谜、每日谜题、场景收藏及必要设置。本说明不包含开发实现或已完成性能验证的承诺。

## 1. 产品闭环与首版边界

**找到下一关 → 倒液体完成对应颜色的瓶子 → 记录通关 → 每完成 4 个新关卡获得 1 块场景拼片 → 每章完成一幅针织房间收藏。**

首版提供 60 个普通关卡，分为 3 章，每章 20 关、1 幅房间场景。普通关卡按顺序解锁，已经完成的关卡可重玩。每日谜题提供独立的一道题及当日完成印章，不推进主线，也不产生场景拼片。

章节命名固定为：第 1–20 关 **Color Studio**，第 21–40 关 **Garden Nook**，第 41–60 关 **Seaside Corner**。

不设登录、金币、体力、倒计时、失败次数或强制购买入口。撤销、重新开始、提示免费且不限次数。收藏是逐步揭示的场景插画，不增加家具购买、摆放或房屋经营系统。首页保留一个清晰的主操作，以及每日谜题、收藏和设置入口。

| 模块 | 首版行为 | 明确边界 |
|---|---|---|
| 普通关卡 | 60 关，3 章 × 20 关，顺序推进 | 不使用未校验的随机开局；不显示不存在的第 61 关 |
| 每日谜题 | 按日期选择预置题，重试不限 | 无排行榜、连签惩罚、补签货币 |
| 场景收藏 | 每 4 个首次完成的普通关卡解锁 1 拼片 | 重玩和每日谜题不重复产出拼片 |
| 辅助操作 | 免费撤销、提示、重开 | 提示不直接完成整关 |
| 额外空瓶 | 普通第 4 关起及每日谜题可自愿观看奖励广告增加 1 个空瓶 | 普通第 1–3 关教学期间隐藏入口；每个实例最多 1 个；重开不会清除已得权益 |
| 存档 | 当前设备本地自动保存，主线和每日独立保存 | 不显示账号同步、云存档或跨设备恢复承诺 |

## 2. 棋盘与倒液体规则

### 2.1 棋盘定义

- 每个瓶子的容量固定为 **4 个单位**，每种颜色在整盘中恰好有 4 个单位。
- 一关有 N 种颜色、N 个带固定目标标签的瓶子，以及 2 个没有目标标签的缓冲瓶。首版 N 为 2、3 或 4；常规完整棋盘为 6 瓶，获得额外空瓶后为 7 瓶。
- 一个目标颜色对应一个目标瓶。橙色圆、绿色三角、紫色菱形、蓝色方形保持全产品一致。瓶身针织外套的颜色只作装饰；目标标签必须清晰独立，避免被误认为装饰色。
- 固定标签只决定通关条件，不限制中途接收液体。橙色目标瓶可以暂时装蓝色液体。已经装满正确颜色的瓶子在整体通关前仍能倒出，不自动上锁。

**Level 12 核心概念图的固定开局**如下，颜色顺序均为顶部至底部，六瓶采用 3 + 3 排列；四种颜色总量各为 4 格：

| 棋盘位置 / 瓶 ID | 液体顺序 | 固定目标标签 |
|---|---|---|
| 上左 / B1 | 橙、绿、紫、蓝 | 橙色圆 |
| 上中 / B2 | 紫、蓝、橙、绿 | 绿色三角 |
| 上右 / B3 | 绿、橙、蓝、紫 | 紫色菱形 |
| 下左 / B4 | 蓝、紫、绿、橙 | 蓝色方形 |
| 下中 / B5 | 空 | 无标签缓冲瓶 |
| 下右 / B6 | 空 | 无标签缓冲瓶 |

该表定义核心页展示状态。提示、倒入后和奖励后等状态应从同一个开局合法演变，不自行改变各色总量。

### 2.2 一次合法倒液体

源瓶非空、源瓶与目标瓶不同、目标瓶未满，并且目标瓶为空或最上层颜色等于源瓶最上层颜色时，可以倒入。

倒入量为：**源瓶顶部连续同色单位数，与目标瓶剩余容量，两者的较小值。** 不能跨过不同颜色取出下层液体，也不能自行选择只倒半段连续色。一次操作结束后，每种颜色的总量不变。

例如源瓶顶部连续 3 格紫色，目标瓶顶层为紫色且剩余 2 格空间，本次倒入 2 格，源瓶保留 1 格紫色。目标瓶若顶层为绿色，本次不产生移动。

### 2.3 点击与反馈

1. 点击非空瓶选中；瓶子轻抬，出现克制的底部选中圈。
2. 再点同一个瓶子取消选中。点击棋盘空白也可取消。
3. 点击合法目标，播放倒液体动画，完成一次移动，随后取消选中。
4. 点击不合法目标，轻微摆动目标瓶并说明原因，如“Bottle is full”或“Match the top color”；源瓶继续保持选中。想改选源瓶时先取消当前选择，避免一次点击同时被解释为换源瓶和倒入。
5. 未选中源瓶时点击空瓶，仅给出“Choose a bottle with liquid”，不制造一次空移动。

动画进行中不接收下一次倒入、撤销或重开操作，避免一连串点击触发多次逻辑提交。后台或关闭打断动画时，下次恢复显示该次已提交移动的完整落定状态，不保留半瓶倒在空中的中间帧。

### 2.4 通关判定

只有同时满足以下条件才通关：所有目标瓶均为 4 格、各瓶全部液体与自身标签一致；所有无标签缓冲瓶均为空，包括通过广告获得的额外瓶。

所有瓶子各自单色、但颜色与目标标签错位，仍未通关。普通规则中的“单色即可”不能作为本产品的通关判定。若满瓶颜色与标签暂时不同，以小提示解释，不使用红色错误警告惩罚正常策略。

## 3. 关卡、教学与提示

### 3.1 难度安排

| 关卡段 | 颜色与瓶数 | 学习或挑战重点 |
|---|---|---|
| 1–3 | 2 色，4 瓶 | 选择源瓶、倒入空瓶、同色合并、匹配目标标签 |
| 4–8 | 3 色，5 瓶 | 连续同色一起倒、容量限制、借用缓冲瓶 |
| 9–20 | 4 色，6 瓶 | 建立完整棋盘习惯，避免过早占满缓冲空间 |
| 21–40 | 4 色，6 瓶 | 增加颜色交错及需要预留空间的局面 |
| 41–60 | 4 色，6 瓶 | 增加规划长度及目标位置安排，不靠缩小瓶子增加难度 |

关卡来自预先校验的题库。每关都要针对“固定目标标签 + 缓冲瓶清空”的最终条件验证可解，并保存一个参考解。不能只验证不带标签的常规排序问题。题目定义包含版本号，避免关卡更新后用新题目解读旧存档。

用于解释规则的独立三步示例，以底部至顶部排列：目标 A 瓶为 `[A,A,B,B]`，目标 B 瓶为 `[B,B,A,A]`，其余两瓶为空。解法是将第一瓶顶部 B 倒入空瓶，再把第二瓶顶部 A 倒入第一瓶，最后将暂存的 B 倒回第二瓶。该示例用于解释空瓶、同色接收和目标标签，**不要求与首关概念图的开局相同**。

首关概念图中，左右两个有液体的瓶子均为上方 2 格橙色、下方 2 格蓝色，另有两个空瓶。若左瓶目标为橙、右瓶目标为蓝，也可以完成：依次将两瓶上方的橙色倒入同一个缓冲瓶，再将左瓶的蓝色合并到右瓶，最后把缓冲瓶的橙色倒回左瓶。正式题库使用与最终教学图一致的定义，不混用示例数据。

欢迎页只有“Start”主操作，不设置登录或设置入口。点击后直接进入首关教学。教学发生在真实棋盘，每次只展示一个动作，允许随时跳过。普通第 1–3 关不显示广告加瓶入口，也不展示插屏广告。在设置中的“如何游玩”重看时，使用独立演示棋盘，不改写正在进行的真实关卡。

### 3.2 撤销与重开

撤销恢复最近一次完整倒液体之前的棋盘，包括该次倒入的准确单位数。没有可撤销记录时按钮禁用并保留可读说明。提示、广告和界面切换不加入撤销栈。获得的额外空瓶不会因撤销消失。

重开需要一次轻量确认，恢复该关初始棋盘并清空本关撤销记录。额外空瓶权益保留，已完成关卡记录、收藏进度、每日印章及设置均不改变。

### 3.3 提示与无路状态

提示从当前棋盘寻找**经验证可以通向通关**的下一步，高亮一个源瓶和一个接收瓶。显示提示不改变棋盘；玩家点击建议接收瓶后才执行正常移动。再次操作任何其他瓶子后，旧提示失效。

必须区分三种状态：

| 状态 | 判断依据 | 给玩家的回应 |
|---|---|---|
| 没有合法移动 | 完整枚举当前源瓶、目标瓶组合，确实无合法倒入 | “No moves available”，提供撤销、重开及可用的额外瓶入口 |
| 当前位置已确认无解 | 求解过程已完成，并证明不存在满足目标标签的路径 | 可说明“Try an earlier move.”，提供撤销和重开；不把加瓶说成必然解法 |
| 提示暂时未找到 | 搜索时间或资源预算用尽，尚未找到已验证解法 | “No hint found yet”，提供撤销或继续；不能显示“无解”或“失败” |

合法移动存在不代表最终可解；提示搜索超时也不代表无解。所有状态均允许玩家退出和继续，不扣次数。提示搜索需避开界面绘制工作；具体时间预算作为实现目标另行验证。提示等待超过短暂反馈时间应显示明确的“Finding a hint…”状态并允许取消。

## 4. 普通进度、拼片及重玩

普通关卡依次开放。首次完成第 k 关后，第 k+1 关开放；每个关卡 ID 只进入“已完成集合”一次。普通进度以这个集合为依据，而不是累计胜利次数。

每章首次完成 4、8、12、16、20 关时，分别取得第 1 至第 5 个拼片。取得第 5 个拼片后，展示该章完整的针织场景；同时开放下一章。场景尚未完成时显示已揭示区域和剩余拼片数量，不能把收藏页设计成可自由摆放家具的装修界面。

**贯穿全部视觉稿的示例：**首页继续 Level 12，Color Studio 已经完成 11/20，拼片为 2/5；第 12 关首次获胜后变为 12/20，拼片为 3/5，并显示“8 levels to complete this scene”。重玩第 12 关获胜只显示完成反馈，不再获得拼片。

通关时先一次性记录棋盘完成、首次完成标记、后续解锁、拼片和场景状态，再展示结果。玩家关闭结果页或应用被终止，已经得到的奖励仍然存在。结果页按钮只负责导航，不作为发奖触发器。

到达拼片节点时，P10 的主按钮是“View patch”，进入 P11 后，主按钮“Next level”才前往下一关。非拼片节点，P10 的“Next level”直接前往下一关。P11 的“View collection”前往场景详情。“View patch”和“View collection”均不触发插屏；只有真正前往下一关的过渡点检查插屏条件。

第 20、40 关同时发生场景完成与新章开放时，尽量合并成一张可跳过的结果卡。第 60 关后主操作变为“Daily puzzle”或“Replay levels”，首页明确展示“All 60 levels complete”，不生成第 61 关。

## 5. 每日谜题

每日谜题与普通关卡采用相同倒液体和胜利规则，棋盘、撤销历史和额外空瓶权益分别保存。按设备本地日历日期从已校验的预置题库选择题目；首版无排行榜和有价值的日期奖励，不增加联网校时与反作弊系统。

当日首次完成后只记录一个当日印章。完成后可重玩，不能再次获得当日印章，也不增加普通关卡进度或收藏拼片。每日页显示当天题目、是否完成、已有印章；日历只作为记录，不以断签提醒制造压力。

跨午夜时，正在进行的每日谜题继续属于开始时的日期。页面顶部显示该日期，不把旧局自动替换为新局。每日页可同时显示“Resume Oct 21”和“Play Oct 22”。首版最多保存一局未完成的每日棋盘：选择新一天的题目时，明确确认“Start today's puzzle? Your unfinished Oct 21 puzzle will be replaced.”；取消则原局保持。已完成的历史印章不会被覆盖。

首页主线“Continue”始终进入未完成的普通关卡；每日卡片使用独立的“Resume daily”文案。两种模式之间切换只切换页面，不覆盖另一种模式的存档。

## 6. 广告策略与额外空瓶

### 6.1 权益生命周期

普通第 1–3 关隐藏“Extra bottle”入口，从第 4 关起开放；每日谜题也可自愿获得空瓶，但每日不展示插屏。点击“Extra bottle”先展示标题为“A little more room”的说明卡，正文为“Watch an ad to add one empty bottle to this puzzle.”，明确按钮“Watch ad for +1 bottle”和“Not now”，限制说明为“One extra bottle per puzzle.”。确认观看才发起广告。若已获得空瓶，入口显示“Bottle added”且不可再次领取。

每个正在进行的关卡实例最多取得一个无标签空瓶。实例由模式、关卡或日期、题目版本及本次开始标识共同确定。重开、撤销、暂退、进后台或应用重启不创建新实例；已经完成后主动重玩才创建新的重玩实例。重玩可以再次选择获得一个空瓶，但不会产生主线或收藏的重复奖励。

每次发起奖励广告前，应用自行创建并保存 `attemptId`，关联正在进行的 `instanceId`。收到有效的 `onUserEarnedReward` 回调后，先持久记录奖励确认和本局权益，再向棋盘添加一个空瓶。使用 `(instanceId, attemptId)` 去重，并以实例最多一个空瓶作为第二层约束；不假设客户端奖励回调一定包含 `transactionId`。额外瓶固定排在缓冲区末位，不改变原有瓶子的身份和标签。重开本局时恢复初始题目，并自动补上这个已经取得的空瓶。

是否发奖以奖励回调是否确认并持久化为准，不以广告关闭事件或视频是否看到了最后一帧为准。`onUserEarnedReward` 已经确认后，即使用户提前关闭广告，也应获得空瓶。纯客户端方案中，若奖励确认回调尚未送达，进程就被终止，不能承诺下次启动自动追回；恢复只能重放已经持久记录的确认结果。

### 6.2 广告结果

| 事件 | 结果 |
|---|---|
| 广告正常结束并确认奖励 | 增加 1 个空瓶，关闭遮罩，恢复原棋盘 |
| 没有可用广告、离线、加载失败 | 展示说明，可重试或返回；棋盘及领取资格不变 |
| 提前关闭且没有奖励确认 | 返回原棋盘，说明“Ad closed. No bottle added.”；仍可继续正常游玩；若随后收到有效奖励确认，仍按去重规则发放 |
| 提前关闭但已收到奖励确认 | 仍然发放空瓶；不显示未得奖的失败文案 |
| 奖励已确认，随后广告界面报错或应用退出 | 以已经确认并持久化的权益为准，恢复时补齐一次 |
| 重复回调或恢复时重复处理 | 通过实例 ID 和应用生成的尝试 ID 去重，不出现第 8 个瓶子 |
| 奖励确认回调未到达就发生进程终止 | 纯客户端无法保证追回；不宣称已经获得空瓶，也不把广告关闭当成确认 |
| 未收到可验证奖励结果 | 保持当前棋盘，不宣称已经获得空瓶；可重新尝试 |

“广告失败”和“无路可走”是两类状态，不能共用混淆文案。广告观看不会重置棋盘、清空撤销记录或中断每日日期。普通的免费撤销、提示和重开入口始终可见。

### 6.3 插屏广告门槛与触发点

前 10 个主线关卡不展示插屏。之后只有在普通关卡首次完成、玩家主动点击前往下一关的按钮时，才检查以下全部条件：

- 已完成至少 10 个主线关卡。
- 距上一次实际展示插屏，已经累计至少 4 次首次主线通关；首次插屏的计数起点设在第 10 关完成时，因此最早在第 14 关完成后的下一关过渡触发。
- 距上一次实际展示任意全屏广告至少 180 秒；奖励广告也更新这个冷却时间。尚无全屏广告记录时，该条件直接满足。
- 插屏已经预加载成功，可以立即展示。

在 P10 或 P11 的“Next level”进入下一关之前检查。P10 的“View patch”、查看收藏、回首页、关卡重玩和每日谜题不触发插屏。条件未满足或广告未准备好就立即进入下一关；广告后来加载成功也不能补弹，不阻塞玩家。下一个符合规则的下一关过渡可以重新检查，不能在正在游玩的棋盘中追补。

仅实际展示插屏后，重置“距上次插屏的首次主线通关数”；奖励广告只更新全屏广告冷却时间，不重置该通关计数。广告展示失败不消耗关卡、不重复提交通关，也不等待网络恢复。

## 8. 保存、暂停和异常恢复

### 8.1 需持久保存的数据

普通及每日各自的模式、题目 ID/日期、题目版本、实例 ID、当前棋盘、撤销栈、额外空瓶权益和奖励去重记录；普通已完成关卡集合；每日印章日期集合；教学状态；Sound、Music、Haptics、Reduced motion、Color symbols 和 Stronger contrast 设置。收藏进度可从首次完成集合推导，避免出现“关卡完成但拼片数量不同”的两套真相。

在合法移动、撤销、重开、奖励确认、通关、设置变更后保存完整逻辑状态。界面选中光圈、倒液体中间帧和短暂提示无需保存。保存事务以落定棋盘为单位，不能分别存源瓶和目标瓶导致液体丢失或复制。

### 8.2 恢复顺序

先读取有效的当前快照；若当前快照损坏，尝试最近一份有效备份，并显示“Restored your last saved progress”。若当前局无法恢复，但独立的完成记录和设置仍然有效，仅重新开始受影响的当前关，保留可读取的其他进度，不自动全量重置。

保存失败时显示简洁明确的提示及重试入口，继续保留内存中的棋盘。未成功写入前不能显示“Progress saved”。返回首页或关闭前的失败提示应说明这次进度尚未保存，而不是让用户误以为退出会安全恢复。

暂停、广告覆盖和应用进入后台都停止接收棋盘操作。恢复时清除失效提示和源瓶选择，展示最后一次完整提交的状态。没有计时器，因此无需因后台时长扣除任何时间或次数。

## 9. 棋盘可读性与动效交互要求

6 瓶采用 3 + 3 排布。获得额外瓶后采用 **4 + 3**，两行瓶子保持相同尺寸，末行居中；不得把第 7 个瓶子孤立压到屏幕底部或盖住辅助按钮。小屏优先压缩装饰区域和标题间距，确保完整棋盘、目标标签及底部操作区均可见。瓶子可见轮廓之外保留足够点击区域，点击目标建议不少于 48 逻辑像素；间距、字号和实际可用宽度需在双端设计验证。

浅色液体保留透明感，同时具备清晰的液面与层间边界。每种颜色配固定形状；“Color symbols”开启时，在每层液体中显示小型同类形状标记，目标标签同时显示颜色和形状。该设置默认开启，避免只靠相近浅色判断。“Stronger contrast”默认关闭，开启后加强液体边界及文字，不必提高整瓶液体的浓度或饱和度。文字与交互图标使用稳定的深色，不把低对比装饰色用于关键指令。

倒液体动效分为选中抬升、移动倾斜、连续液流、回位落定。倾斜时液面仍朝重力方向保持水平，液体体积同步减少/增加；不能把四层矩形贴图整体随瓶旋转。动画只覆盖参与移动的两个瓶子和液流，不让整页针织场景持续抖动。减少动态效果开启后，用短促液位变化与高亮替代大幅位移和倾倒，保留完整逻辑反馈。

目标是通过可复用的瓶子绘制、预渲染装饰及局部动画适配 Flutter 双端；视觉稿不把复杂实时 3D、全屏折射或实时流体模拟设为功能前提。这里是实现约束与设计目标，不是已经测得的帧率结论。

## 12. 视觉与实现交付约束

### 12.1 颜色和字体目标

| 用途 | 色值目标 / 字体 | 约束 |
|---|---|---|
| 浅蜜桃橙液体 | #EBC69B | 圆形；保留透光感 |
| 浅叶绿液体 | #B9D89F | 三角形；不要与蓝色只靠亮度区分 |
| 淡紫液体 | #C6AADB | 菱形；不做荧光发亮 |
| 浅蓝液体 | #A9D4E6 | 方形；空瓶必须能区分 |
| 品牌背景 | 明亮天蓝，约 #82DFF1 | 细腻轻微明暗变化，避免强烈彩虹渐变 |
| 控件与正文 | 奶油针织底＋深蓝文字 | 纹理集中在边缘，文字区保持清楚 |
| 英文 UI 字体方案 | Nunito 600 / 700 / 800 或同类清晰圆体 | 图中字体为视觉参考；不要把文字烘焙为最终按钮资源 |

瓶子目标由独立标签决定，瓶套的装饰色不参与规则。默认显示颜色形状标记。液体分层的接触面平直连续，仅最上层有弯月面；下层不可各自带圆角、投影或空气缝隙。

### 12.2 动效节奏

| 动作 | 设计时长目标 | 表现与逻辑 |
|---|---|---|
| 选中 | 约 100–140 ms | 轻抬 4–6 逻辑像素，出现底部选中圈 |
| 移动与倾斜 | 约 150–180 ms | 源瓶移动到目标上方，液面按重力保持水平 |
| 倾倒 | 约 300–480 ms | 连续液流，源和目标的液量同步变化 |
| 回位与稳定 | 约 180–220 ms | 落回原位，轻微液面收敛 |
| 通关与拼片 | 约 500–700 ms | 少量布片庆祝，可直接继续，不强制等动画 |
| Reduced motion | 约 120–180 ms | 简短液位变化和高亮，省略大幅位移 |

一次完整倾倒以约 0.7–1.0 秒为体验目标，具体数值要在交互原型中调节。模型一次提交最终棋盘，动画表达已提交的变化；后台中断后恢复完整落定状态。若存盘失败，保留内存棋盘并提示重试，不能显示保存成功。

### 12.3 Flutter 资源结构与性能目标

针织房间、家具、外套、玻璃边缘与静态阴影拆成可缓存的预渲染资源；液体、液面、图形标记、选中反馈和水流独立绘制。禁止把整幅游戏页面作为最终交互界面贴图。

采用局部 CustomPainter 动画与可监听的重绘驱动，减少反复构建、布局整个页面；保持语义与点击区域独立。[S1] 背景与静态房间复用缓存，避免频繁离屏合成、大面积透明层和不必要的裁剪。[S2] 暂停和弹窗使用简单半透明色罩，避免持续全屏模糊；官方文档也提示滤镜范围与成本需要控制。[S3]

常规六瓶采用 3+3；七瓶采用 4+3，两行瓶子按同一尺度渲染。基础布局目标 390×844 逻辑像素，另外验证窄屏、系统大字体与安全区域。小屏先缩减装饰区域，保留清晰液层、标签和按钮。图中瓶子尺寸为美术参考，最终使用同一个容量为4的几何模型，不分别手调两行宽高。

交互目标在双端统一按至少 48×48 逻辑像素设计；小文本目标对比度至少 4.5:1，大文字至少 3:1，同时验证系统字体放大。[S4] 动态棋盘还需提供可读的瓶号、目标颜色及当前层序语义。

性能以中端 iOS / Android 设备稳定 60 fps 为目标，实际需在 Profile / Release 模式实测。此处是设计与实现约束，本轮没有真机性能结果，也没有产出可直接使用的分层美术切图。

## 13. 广告与隐私依据

奖励广告应在展示前清楚说明奖励，并由玩家主动选择；拒绝或跳过仍能继续正常游玩。[S5] SDK 将奖励回调与广告关闭事件分开，本方案据此使用奖励确认＋本局唯一权益＋持久化去重。[S6] 插屏只在关卡之间的自然过渡点检查是否展示。[S7] 前10关、4次新通关和180秒是本方案的产品频控假设，不是平台规定，也不是已通过数据验证的最优值。

每次启动更新 UMP 状态，请求广告前以 canRequestAds() 为准。Manage ad privacy 入口按 SDK 对隐私选项入口的要求呈现；本页图示为该入口可用时的状态。若 SDK 判定不需要入口，则隐藏这项操作，保留隐私政策与设备权限。离线或表单加载失败时保留现有选择，提示重试，不伪造保存成功。[S8]

如涉及需要跟踪权限的行为，使用系统 ATT 授权；应用内按钮只导航到本应用系统设置，不制作可直接修改 ATT 的自定义开关，也不以空瓶或功能奖励换取授权。[S9] 具体 SDK 的数据清单、正式隐私政策与商店披露在发布前按实际集成内容完成。
