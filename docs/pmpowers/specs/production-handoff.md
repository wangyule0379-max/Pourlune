## 2. 文案交接

原 `UI_copy.csv` 用 `(screen_id, element)` 作稳定来源身份；增量 CSV 的 `state / key / destination` 是原型导出记录，不能直接作为最终本地化键或导航规则。

实施时建立英文 ARB：原键映射为稳定语义键，保留 `{level}`、`{earned}`、`{total}`、`{date}` 的类型与含义；同文案跨状态复用同键，确需不同语义才新增。章节名与品牌不变；日期由本地日期格式生成，不能把设计稿日期写死。对每个新增键记录来源 AC/D 编号，并检查按钮的实际结果。增量状态修复验收后再冻结文案映射，避免把当前错误路由带进 App。

## 4. 第一个可玩闭环的实施交接

以下为接下来的开发任务顺序，尚未宣称实现；具体建工程由开发任务执行。

1. **纯规则和内容读取**：采用 2/3/4 色夹具；实现合法倒入、固定目标胜利、撤销及重开。将 Python 的手算案例与原 15 步快照迁为 Dart 行为测试。对应 AC-01～03、AC-07、AC-35 的样本部分。
2. **一次动作与保存**：界面发意图，核心给完整状态，SQLite 原子提交；保存失败保留待保存数据；通关与奖励去重；旧版本迁移样本先写测试。对应 AC-09～12、AC-23～24、AC-33。
3. **素材绘制探针**：ART-01/02 样本到位后，实际运行 6/7 瓶、倾倒、撤销、取消动画和强退恢复；窄屏/大字号保持可点；无素材时只验证规则，不通过最终视觉。
4. **提示 isolate**：完成可取消、有时限的搜索；区分无解、超时、无合法移动；结果校验 instance_id 和 board_revision。对应 AC-05～08。
5. **一关闭环与免费路径**：启动→进局→倒水→保存→通关→收藏→恢复。先断网验证；普通/每日两个槽和重玩再扩展。
6. **服务适配**：前述闭环成立后接 Firebase / AdMob 测试配置，验证真实 SDK 回调、冷却和失败降级。替身测试不能替代真实 SDK 联调。

每步提供运行命令、版本/设备、测试结果和未验证项；最低系统版本由插件要求与实际构建落定。当前不为了消除 doctor 警告升级所有工具、不提前创建业务服务器。

运行设备覆盖至少含：iOS 与 Android 各一组代表设备；选定最低系统和当前系统；窄屏、大字号、减少动态效果；离线/弱网；前后台切换、强退与低空间保存失败。具体型号在设备可用时记录，不假设本机已经拥有全部设备。
