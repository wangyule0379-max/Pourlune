# Pourlune 验收与内容交付清单

更新日期：2026-10-21（Asia/Taipei）。对应 [产品规格补充稿 v1.1](PRD-supplement-v1.1.md)。以下均为待执行验收，不是 App 已通过的测试结果。

## 1. 规则验收矩阵

| 编号 | 前提与操作 | 应有结果 |
|---|---|---|
| AC-01 | 源顶部 3 单位同色、接收瓶余量 2 且颜色兼容，执行倒入 | 只转移 2，算一步，颜色和总量守恒；撤销恢复原状 |
| AC-02 | 点同瓶、满瓶、顶部异色瓶或空源 | 按选择规则取消或反馈，不产生倒入、步数及撤销记录 |
| AC-03 | 所有非空瓶单色，但目标标签不匹配或缓冲瓶仍有液体 | 不通关；匹配所有目标且缓冲瓶空后仅结算一次 |
| AC-04 | 教学中退出、恢复、跳过、完成后再重玩 | 步骤与棋盘一致恢复；跳过后可自由操作；不强制重教 |
| AC-05 | 已选瓶 A 时请求建议从 B 到 C 的提示 | 自动选 B；点 C 才移动；取消清选择，棋盘变化清旧提示 |
| AC-06 | 分别构造可解、证明无解、搜索超时、无合法移动状态 | 四种结果反馈准确；超时不称无解；可使用免费救援 |
| AC-07 | 加瓶前后分别倒入，再连续撤销，最后重开 | 不收回额外瓶；撤销内容与步数正确；重开清历史且保留瓶与额度使用状态 |
| AC-08 | 提示搜索过程中快速取消、重开、切后台 | 旧结果不影响新棋盘，界面保持可操作，无幽灵提示 |
| AC-09 | 普通首次通关并重复触发结算回调 | 完成、解锁、拼片、广告计数只提交一次 |
| AC-10 | 在通关保存前、写入中、写入后分别强退 | 恢复为上次完整状态或完整新结果，无部分解锁或漏拼片 |
| AC-11 | 通关保存失败，点 Next／Home，再点 Retry | 失败期间不导航、不展示广告、不宣称已保存；成功后执行一次原导航 |
| AC-12 | 已获得拼片，在揭示动画中强退再进入收藏 | 拼片仍在；可恢复呈现但不重复发奖，重访不反复领奖 |
| AC-13 | 首次依次通过 1～16，广告一直可用且冷却满足 | 1～12 不检查；13、16 才有检查机会，点 Next 才展示 |
| AC-14 | 第 13 关无库存／离线／冷却中，14 关恢复条件 | 13 不展示且保留资格，14 的新结算 Next 可展示；成功后下次最早 17 |
| AC-15 | 第 16 关同时发拼片，第 40 关同时完成章节 | 16 先奖励，Next 后检查；40 跳过但保留资格，41 的合格 Next 可再检查 |
| AC-16 | 检查点点 Home／View collection，或强退后恢复结算 | 累计资格保留；返回、重启、广告迟到不补弹，仅后续新的主线首次通关过渡可再检查 |
| AC-17 | 距任意全屏实际展示 179 秒、180 秒；另测后台和改系统时间 | 179 不可再展示，180 可按其他条件展示；后台时间计入；异常时钟保守处理，不绕过冷却 |
| AC-18 | 达加瓶上限、广告无库存、处于冷却、授权不允许时点入口 | 正确状态文案；不展示广告；免费提示、撤销和重开可用 |
| AC-19 | 激励奖励回调早于关闭、晚于关闭、重复、没有奖励仅关闭，后续请求后原确认迟到 | 仅有效确认发奖；单独关闭结束等待而不发奖；同实例不出现两瓶 |
| AC-20 | 已确认待发奖后强退或保存失败；恢复／重试 | 已持久化确认可恢复发给原实例；未落盘确认的限制不被伪装为已到账 |
| AC-21 | 奖励确认迟到时未完成原实例已替换，或原局已完成 | 新局不获赠；未完成原局可按请求保留状态恢复且明确替换；已完成原局只记归属，不重开或重复主线奖励 |
| AC-22 | 主线 12 玩一半，确认重玩 3 后点首页 Continue，再完成重玩 | 进入 Replay · Level 3；无重复拼片／广告计数；完成后选关或回首页 |
| AC-23 | 题库更新后继续与重开旧局，再创建新实例 | 旧局用旧定义；新实例用新定义；首次通关身份不因版本重复计算 |
| AC-24 | 普通局与每日局交替进入；存档恢复失败 | 两槽互不覆盖；只恢复或重开受影响实例，不误清全局进度 |
| AC-25 | 昨日每日局未完成，跨日选择继续／取消替换／确认开始今天 | 继续保留昨日；取消不丢旧局；确认且保存成功才替换 |
| AC-26 | 跨日完成旧题，随后玩今天；点击历史与未来日期 | 印章按各题原日期；历史只读，未来不可挑战，不可补签 |
| AC-27 | 修改时区／日期回到已完成日期，或更新每日题目录 | 同日期不重复领奖；当前实例不换题；当天完成后可 Replay；新实例遵循映射版本 |
| AC-28 | 第 60 关通关并完成最后收藏 | 无 Next level，无插屏；有每日、收藏、重玩入口 |
| AC-29 | 全通后次日进入首页，分别测试今日未完成／已完成／有重玩存档 | 主次入口和状态正确；不暗示存在未交付的新章节 |
| AC-30 | 每日题轮换到末尾再进入下一天；目录缺失 | 按已声明顺序循环，记录按日期独立；缺失时明确不可用且主线仍可玩 |
| AC-31 | 小屏、最大支持字号、色觉差异、关闭声音、减少动态效果 | 标签与按钮可辨认可操作，胜利与错误反馈不只靠颜色／声音 |
| AC-32 | 连点 Next／广告按钮、广告期间后台和返回、展示失败 | 一次展示或一次跳过，一次导航，无重复实例或奖励 |
| AC-33 | 系统强退发生在倒入动画中 | 恢复完整合法棋盘，步数与撤销历史一致，无半笔动作 |
| AC-34 | 关闭网络，启动并继续主线／每日已含题目，使用免费辅助 | 核心玩法可用，不等广告初始化；广告入口准确降级 |
| AC-35 | 回放 60 关所有参考解及全部每日题参考解，均不加广告瓶 | 每步合法、颜色守恒、最终满足标签与缓冲瓶胜利条件 |
| AC-36 | 重复发送完成、广告与奖励事件，并检查分析结果 | 按实例／请求／机会去重；检查次数不被误作曝光，确认与到账可区分 |

## 2. 五条端到端走查

| 流程 | 步骤 | 通过条件 |
|---|---|---|
| 普通首次通关 | 进入第 11 关 → 倒入 → 保存 → 结算 → Next | 仅解锁与计数，无广告机会；下一局正确 |
| 奖励与广告重合 | 首次完成第 16 关 → 拼片揭示 → Next → 广告 → 17 关 | 拼片归属已保存且先呈现；广告一次，导航一次 |
| 加瓶后立即通关 | 第 13 关主动看激励 → 确认到账 → 使用空瓶并通关 → Next | 额外瓶参与求解与胜利判断；插屏因冷却跳过 |
| 跨日未完成 | 昨日开局 → 跨日 → 继续旧题 → 完成 → 开始今日 | 两个日期各自记录；普通主线存档不受影响 |
| 结算时强退 | 第 12 关最后一步 → 在各保存阶段退出 → 恢复 → 查看收藏 | 不丢既有进度，无半份奖励，无重复计数，可继续 |

单关交付模板字段：puzzle_id、version、chapter、capacity、bottles（自底向上记录每单位颜色）、target_labels、reference_moves（源索引／目标索引）、reference_step_count、difficulty_intent、playtest_notes。

内容作者须同时提供索引起点、颜色枚举和数组方向说明；验证器与客户端使用同一题目解释。空瓶用空数组，缓冲瓶目标标签为空，不用装饰色表达目标。

## 4. 决策与质量结论

产品基本结构和主页面 UI 已存在。本次原件核对纠正了固定广告检查点、每日不可重玩和若干“缺失”误判。补充规格仍需 UI 状态变体、内容生产与运行验证。

上述 36 条为待执行的 App 验收标准；静态原稿检查不能标记其运行结果通过。UI 层证据和增量任务见 ../../design/review/original-design-review.md。

进入发布验收仍需完整题库、完整收藏进度资源、真实 SDK 与设备验证。不要把“规则已写”“静态稿已检查”“App 已测试”合成一个完成状态。
