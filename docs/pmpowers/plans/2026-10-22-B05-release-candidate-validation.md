# B05 首版候选验证与交接

2026-10-22。既定首版范围的最后一个完整工作包；本计划准备完成不等于已经派发。启动条件：架构方完成 B04 可独立验证的实现验收并推送，明确保留真实 SDK 与外部依赖门槛。沿用 `codex/offline-foundation` 和现有执行聊天。

## 执行目标与边界

交付可复现的内部候选、完整 AC 证据索引和真实剩余依赖。连续完成以下八项，不做完一项就等待提醒。遇到账号、签名或设备缺口，标出受阻子项并继续其他工作。不新增产品能力，不创建账号、不部署生产网站、不代签条款、不提交商店、不购买服务。原始 UI 和素材商业权属状态保持真实。

|任务|具体工作及完成条件|
|---|---|
|B05-01 全量验收矩阵|逐条映射 AC-01～36 到实现、有效自动检查、真实平台流程和剩余缺口；区分历史已验、本批复验、控制运输/替身、真实 SDK、外部未验。复用已有有效证据，按风险补缺，不靠增加镜像测试充数。|
|B05-02 五条端到端流程|按 acceptance-and-content-readiness 的五条流程跑真实 Flutter/sqflite。隔离库准备起点可以使用明确的 QA 数据，但不把种子当真实游玩或 SDK 奖励；至少覆盖主线11、16拼片先呈现、13激励后冷却、跨日双槽、12结算强退。真实广告无库存时仅标对应子链未验，保留免费路径和受控状态测试。|
|B05-03 恢复与迁移|非空 schema1～4 到5及 snapshot2；冷启动/后台/动画中真实进程 terminate→launch，保留同一安装与库。验证完整旧/新棋盘、奖励/拼片幂等、普通/每日槽隔离、已保存确认恢复和未落盘限制。运行器重装不能当进程恢复。SQLite 写故障/读取故障分开注明，保护免费导航与 Retry。|

## 协作、证据与验收

执行方管理 app、核心、工具、CI 和自己的交付/证据；架构方管理 plans、tracking 和 review，独立复跑必要检查并操作真实 App。测试只清理显式命名测试数据库；不得清理普通用户存档。每项日志标命令、工作目录、平台、模式、测试数据及证据层级。原生截图在测试 runner 卸载前复制。

真实 Firebase DebugView/Crashlytics/Remote Config、AdMob 展示/奖励/原生中断、Android 与代表真机、域名邮箱和权属受外部依赖约束，仍是首版发布门槛。能够独立完成的 B05 工作通过，不代表这些门槛已经通过，也不意味着首版可上架。

架构方验收后提交并推送开发分支；若只剩需要用户交接的外部事项，集中一次说明并暂停无效自动轮询。继续开发的授权不包含生产发布。
