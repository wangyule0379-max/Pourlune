# 倒水出水口偏离：根因定位

2026-10-26，用户要求找原因。本轮只做源码与既有真实原生帧对照；没有修改生产代码、运行Flutter/设备或新建发布。

## 已确认原因

1. `app/lib/presentation/flame_board/geometry.dart:113` 的 `lip(direction)` 仍使用旧常量 `(±0.08 × width, 0)`。结合 `imageRect` 的 `-0.10 × height` 偏移，这个点对应美术裁片的 `(0.58, 0.10)` / `(0.42, 0.10)`，落在可见瓶口前侧针织圈附近，未对齐开口/实际出水边缘。它是2026-10-22留下的几何常量，2026-10-25改用当前参考素材和轮廓时没有同步标定。
2. 瓶子与水流确实共用相同旋转/缩放变换，因此不是两者旋转公式不同；错误发生在变换前的局部出水点。`streamStart` 在394行直接变换这个旧点。水位角度求解 `pourAngle` 和运动对齐同样依赖它，单独偏移一条水流会造成新的不一致。
3. `paint.dart` 先画完所有瓶体及前针织口圈，之后167–219行才画整段水流。流柱起点因此直接盖在前口圈上；现有裁剪只约束接收瓶内部，没有处理出水瓶前唇的遮挡关系，强化了“从针织侧面出水”的观感。

## 实际证据及漏检原因

已实际查看 `evidence/orange-pour-gap-20261026/single-frames/frame-20.40.png` 与 `up-frames/frame-24.60.png`：紫色源瓶向右下倒橙水、米白源瓶向左上倒橙水，两帧均可见水流起点落在前侧口圈，而非从开口顺接。另看生产 `reference-play.png` 对照源口圈与开口。geometry/paint/frame及该美术文件均逐字节核为已发布15源 `70d9b59`，不是旧截图与新代码混用。

旧几何测试将 `streamStart` 与同一个 `shape.lip` 函数相比较，只能证明公式自洽；没有独立校准真实素材开口。后续可见水流测试检查接收瓶水流连续，口圈间距测试检查两圈不重叠，均未覆盖出水点与源瓶开口的关系。父上一轮看图也漏掉了这一点；此前颜色/间距接受不等于这个问题不存在。
