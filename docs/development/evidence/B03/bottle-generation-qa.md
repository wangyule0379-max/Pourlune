# B03 瓶体 imagegen 候选生成与透明度自查

2026-10-22。执行证据，不是独立视觉验收。仅生成 ART-01 分层运行素材；原始参考、控制器、棋盘及其它资源未在本子任务内修改。

## 来源与方法

先用 `view_image` 查看原始 `boards/00_Approved_Style_Reference.png` 与 `boards/02_Tutorial_Play_Pause.png`：采用其中空瓶的透明玻璃、圆润瓶肩、厚奶油色针织边及柔和 3D 光照。目标标签、彩色瓶口、液体和所有 UI 不进入运行素材。

内建 `image_gen.imagegen`，每次 `transparent_background=true`：先后层、一次去外光晕编辑重试、前层、独立阴影，共四次。后层重试让中央透明度从 alpha13 增加到82，且未完全消除低 alpha 残留，因此未选用。前层参考首张后层和两份原图来对齐；阴影单独生成，没有瓶体输入。

精确提示词、输入、生成原始绝对路径、所有选用／弃用结果、SHA-256 与 alpha 数值保存于 `bottle-generation.json`。选用文件直接原字节复制到以下两处，无缩放、裁切、阈值清理、程序绘图或重新编码：

- `docs/design/production-candidates/runtime/bottles/{back,front,shadow}.png`
- `app/assets/art/bottles/{back,front,shadow}.png`

请求目标 512×768；实际均为 **1024×1536 RGBA PNG**，比例仍为 2:3。三份候选与应用副本逐字节一致。

## 目视与像素检查

| 层 | 目视结果 | alpha=0 比例 | alpha>4 的实际包围盒（右／下不含） |
|---|---|---:|---|
| back | 空玻璃壳，淡青色边缘与玻璃底；无液体、标签、符号、文字、针织或接触阴影。中央像素 alpha13/255。实际含完整口沿及部分前向反光，不能宣称是严格只有后半口沿的精确拆分 | 55.1607% | `(214,195)-(810,1430)` |
| front | 奶油色针织开放口环、肩部／侧边及下缘；两条窄纵向白玻璃反光。中心没有玻璃面板，中心像素 alpha0；无液体、标签、文字或独立接触阴影 | 75.2379% | `(198,163)-(828,1410)` |
| shadow | 只有靠画布底部的柔软蓝灰椭圆，无瓶子／其它物件。实际最大 alpha167/255，比提示要求的25%浓；建议运行时绘制 opacity≈0.4 后观察 | 93.2337% | `(71,1367)-(952,1500)` |

所有图片均带真实 alpha。前层中央开口 ROI `x=.32..68,y=.32..82` 的 alpha 范围为0–1，96.6121%像素严格为0，**没有 alpha>4 像素**；更中央 `x=.35..65,y=.32..80` 98.0317%为严格0，其余为alpha1。请求的完整窗口 `x=.26..74,y=.30..85` 包含侧边纱线／玻璃反光，不能把该整个矩形错误标为全透明。

生成器仍在外部背景及窗口留下很淡的 alpha1–4 噪声／光晕（JSON提供包含所有非零值的原始包围盒）。没有把它伪称为“外围所有像素严格全透明”；因本任务明确禁止程序修图，保留生成原始像素并交给主任务在实际背景检查。黑底预览中的亮雾比实际低 alpha 叠加更明显，但真实运行外观需要 Flutter 核验。

## 运行几何交接

坐标基于 1024×1536 原始全画布，不能按截图外观静默裁切：

- 后层玻璃躯干约 `x=.211..789,y=.30..93`；瓶口视觉锚点约 `(.50,.15)`。上部开口口沿实际从 y≈.127 开始。
- 前层主轮廓较玻璃壳略宽，前层底部1410 vs 后层1430；建议前层额外向下 **20px /1536=.0130208画布高度**，让针织下缘与后层底缘一致，口环自然包住玻璃口。该校准来自源像素边界，尚非运行通过。
- 建议液体窗口起点 `x=.30..70,y=.31..85`，或由主任务根据针织覆盖与玻璃内壁校准剪裁路径；中央透明矩形检测为 `.32..68,.32..82`。不能把 alpha ROI 检测框直接当作最终液体 mask。
- 阴影视觉中心约 `(.5,.936)`，alpha>64 的核心区域 `(205,1397)-(798,1476)`；外部柔化范围更大。建议初始 opacity0.4，仍需实际画面核验。
- 主任务保持 width×148 的运行艺术画布及既有标签布局，通过绘制层位移／液体边界校准实际口锚点与动画水流。此处不修改消费者代码。
