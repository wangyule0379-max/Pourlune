# 远端Mac：上传前工程与分发后真机分开

2026-10-23新确认优先于BR02/BR03早先的直连条件：用户手机不能USB连接远端Mac，只经TestFlight/Google Play安装。**USB直连真机不是本项目上传前一律硬门槛。** 本文件调整验收时序，不把任何未测试项改为通过；最低OS/16KB/读屏/音触觉/性能仍是具名风险，需要分发后适用设备证据。

## 阶段A 当前可做的提交前工程

确认源/锁/版本、正式ID、签名与证书有效性、包格式、SDK/权限/隐私manifest/资源/符号；校验公开目的地输入、免费与广告关闭、构建门控。适用自动规则/事务/迁移证据继承并对新改动定向测试。网页/联系方式/声明和Android真实签名尚未齐备不能假称整个包就绪；没有USB不阻止这些工程，也不以再跑旧QA来补真机栏。

iOS现有Store IPA不是直接侧载包；AndroidAAB必须有上传签名，不能由debug签名APK代替。实际新包在真实资料输入后采用新目录/构建号，冻结hash，提供用户可审的“精确版本+平台+轨道+受众+SDK运行条件”，届时才处理单独分发授权。当前不上传/运行prod、不代签或创建测试组。

## 阶段B 获得明确生产运行与商店分发授权后

1. **iOS资格先判定**：本人是否已经是有该App访问权限的ASC合资格内部用户，不能凭AppleID或Team会员身份猜定。已有资格才走内部组Pourlune Beta；没有资格走外部测试和平台需要的Beta审核，不为测试新授角色或扩大IAM。外部首构建审核和内部可测是不同状态。使用App Store官方TestFlight，不要求开发者模式、USB或安装来源不明证书。
2. **Android最终为closed**：本人Google账号/商店地区与获授权closed名单匹配，平台处理和对应问卷完成后，经正式opt-in入口/Play安装。internal至多为中间测试，不替换closed目标。核对实际Play app-signing证书与版本，不能把本地upload-key证书当最终安装证书。此处尚未创建轨道/组或发邀请。
3. 先本人自己的账号及少量受控名单；邮箱仅在实际需要的控制台/私密渠道使用，不入仓库。首次运行的SDK/RC可能处理安装数据，须明确允许范围；采集选择仍off、广告disabled。授权运行不自动授权启用采集/真实广告/所有地区或公开链接。
4. 手机记录TestFlight/Play实际构建标识、型号/OS/地区、实际安装时间和可观察进度；平台处理/审核/可见性/安装分别记录，不能上传完成就称测试者可装。不要求UDID/IMEI/ADB/SQL导出或刷机清档。

## 阶段C 首包与N→N+1

首包实际分发时不存在旧正式安装N，则只验干净安装/正常保存恢复，升级栏记“未执行：无旧N”。后续更高真实构建号N+1通过同一分发来源更新，保留原安装/账号/数据，不卸载。核对主线进度/当前瓶层、可用Undo历史、每日日期/槽、拼片/Collection、免费辅助、音频/减少动态和隐私选择。用户看不到实例ID/revision/schema时填不可见，不能要求调试模式导库；完整SQLite一致性仍依独立自动/QA证据，不能与手机可观察结果混为一项。

失败时保留旧安装和数据，先记录构建/平台错误和复现；不要求降版本或卸载“试试”，不承诺跨设备/云恢复。必要定向修复后用兼容的新构建复验。手机关闭App再开是同安装恢复，不能通过商店重装冒充；实际强退/保存失败边界若不可控，保留未验，不让用户制造磁盘耗尽。

依据：[内部测试资格](https://developer.apple.com/help/app-store-connect/test-a-beta-version/add-internal-testers/)、[外部测试](https://developer.apple.com/help/app-store-connect/test-a-beta-version/invite-external-testers/)、[Play轨道](https://support.google.com/googleplay/android-developer/answer/9845334?hl=en)。不预设这批设备可覆盖所有最低OS/页大小；没有分发/手机实测结果时保持风险，不再形成“无USB不能上传”的循环。
