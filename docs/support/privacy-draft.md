# Pourlune privacy notice — DRAFT, not published or legally approved

Prepared 2026-10-22 for the B04 development build. The operator, production app identities, contact address, public policy URL, applicable regions, retention/deletion processes and store disclosures require the owner's review before release. This document is not the in-app policy destination.

Pourlune stores puzzle progress, undo history, collection pieces and settings on your device. Core puzzles and free Hint, Undo and Restart work offline. No player account, cloud sync, business server, subscription or payment flow is implemented. Reset Progress removes local gameplay records; it keeps device preferences. Uninstalling or clearing application data may remove your progress.

Optional ads use Google Mobile Ads and Google's User Messaging Platform. Ads are requested only when the SDK reports eligibility; the applicable official privacy form and privacy-options entry come from that SDK. Requests in this implementation use non-personalized ads. This does not mean that advertising has no data processing: the SDK may process device/app/network information, identifiers and ad interactions. Production consent-message configuration and regional behavior still require an owned AdMob application and device validation. This build does not request tracking authorization or IDFA access. A future tracking configuration must add and verify the applicable official ATT flow first.

An optional rewarded ad adds one empty bottle to its original puzzle only after the SDK delivers a reward confirmation and the local transaction succeeds. Closing an ad alone is not a reward. The app cannot recover confirmations it never received or saved. An interrupted request is explained in the app. A valid reward for a replaced puzzle requires explicit confirmation before replacing that slot with the earlier saved puzzle.

Gameplay analytics and crash sharing are separate, off by default choices. With no valid Firebase configuration, these services are disabled even when a local choice is saved. When enabled in a correctly configured build, Firebase Analytics receives bounded gameplay events (puzzle IDs/version, random local instance/request IDs, completion and effective foreground time, helper counts, ad checks/impressions/dismissals, reward confirmation/grant and save outcome categories). We do not include full boards, email, feedback bodies or arbitrary exception text in these events. SDKs can also generate technical and automatic events; this is not a claim that only manual events exist. Automatic screen reporting and advertising-storage/user-data/personalization consents are disabled by this implementation.

Crash sharing includes technical diagnostics and may include crash reports stored locally before sharing was enabled. Automatic Crashlytics report upload stays off; app upload requests are gated by the separate choice. The native SDK may cache crashes locally even when sharing is off. Turning sharing off stops new app upload requests and requests deletion of unsent reports; it cannot recall an upload already queued or sent. SDK calls do not provide a delivery/deletion receipt. The app sanitizes exception categories but stack traces and SDK device/app information remain diagnostics.

Firebase Remote Config, if configured, retrieves bounded feature flags and disabled puzzle IDs using Firebase installation infrastructure. Disabling analytics does not disable all Firebase processing. Missing, invalid or unavailable remote values preserve local defaults/last validated values. Remote flags do not alter an active puzzle or revoke an earned reward.

Privacy choices are available in Settings. A failed local save or native synchronization is shown with Retry, and app event sharing is blocked while unresolved. Advertising privacy options appear when Google's SDK requires them. Support links and email open an external browser/mail app only after a player chooses them; the app does not upload a board or send feedback automatically. This build has no approved public destinations and accurately reports them as unavailable.

Data recipients, retention, controller identity, international transfers, user requests, children's eligibility, legal bases and final store disclosures must be completed from the actual production configuration.
